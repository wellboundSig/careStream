HCHB duplicate check — precise SQL (from schema-map / schema-usage)
===================================================================

USE THESE TABLES
----------------
  dbo.CLIENTS_ALL            ~21,093 patients   PK pa_id
    pa_ssn, pa_medicaidnumber, pa_lastname, pa_firstname, pa_dob,
    pa_legacymrnum, pa_status, pa_archivestatus

  dbo.CLIENT_EPISODES_ALL    ~37,230 episodes   PK epi_id
    epi_paid  →  CLIENTS_ALL.pa_id
    epi_mrnum = HCHB medical record number
    (also denormalized epi_ssn / epi_lastname / epi_firstname / epi_dob —
     prefer CLIENTS_ALL for identity; use episodes for MRN)

DO NOT USE for matching
-----------------------
  CLIENTS_ALL_BAK (empty), SNAPSHOT_*, PC_PATIENTS1 (huge staging),
  REFERRAL_REQUESTS (only 39 rows), purge.*, WORKER_* (staff not patients)


MATCH PRIORITY (ideal)
----------------------
  1. SSN            CLIENTS_ALL.pa_ssn
  2. Medicaid       CLIENTS_ALL.pa_medicaidnumber
  3. MRN            CLIENT_EPISODES_ALL.epi_mrnum  (+ pa_legacymrnum)
  4. Name + DOB     CLIENTS_ALL.pa_lastname + pa_firstname + pa_dob
                    ← this is the marketer path


HOW THE SYSTEM USES THIS
------------------------
  Closet PC loads patients + latest episode (active and discharged) with
  LOAD SQL in sql_queries.py, HMAC-hashes them in memory, refreshes every
  5 minutes. DELETED episodes are ignored.

  CareStream / curl sends only HMAC digests over the internet.
  Agent answers match flags plus hchb_case:
    case_status, episode_status, episode_start, discharged_on,
    has_active_episode, episode_count
  No names / SSN / MRN / DOB come back from HCHB.

  Strong name+DOB on an active case → duplicate true (do not open a new chart).
  Strong name+DOB on a discharged case → former_patient true + discharge date.

SOC/ROC VISIT CHECK
-------------------
  V_AGENTVISITTIMEREPORT   Client Name, Visit Type, Visit Date, Discipline
  Join identity from CLIENTS_ALL (name + DOB) for hashing only.

  Skilled visits only (Discipline not HHA/HA).
  Visit Type must classify as SOC or ROC and match the CareStream episode.
  Date window is scheduled date ± 1 calendar day.

  LOAD SQL: build_load_visits_sql() / build_load_visit_identity_sql()
  in sql_queries.py. Results over AWS are match flags + visit date/type only.
